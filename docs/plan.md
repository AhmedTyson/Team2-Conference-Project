## A. Objective

Build a verified knowledge base of the existing application:

- Audit what is actually implemented (backend + frontend + schema + API contracts).
- Verify the existing test suite against the real codebase; run the full suite and record a trustworthy baseline.
- Document what the application actually does (`docs/functionality/*.md`, `docs/routes.md`) — every claim source-verified.
- Produce `docs/final-audit-report.md`.

- **Backend scope:** Laravel 13 app: routes, controllers, services, models, policies, events/listeners, jobs, mail/notifications, enums, seeders, migrations (read-only).
- **Frontend scope:** EXCLUDED by user decision. No frontend files, API-consumption audit, or static checks. Any mention of `frontend/` elsewhere in this doc refers to its existence as repo structure only.
- **Database scope:** schema as-is; verify `migrate:fresh --seed` and migration state. **No schema changes.**
- **Testing scope:** run existing PHPUnit suite; write tests ONLY where a gap against implemented behavior is confirmed and approved; no tests for nonexistent features.
- **Documentation scope:** `docs/plan.md`, `docs/functionality/{account,catalog,trips,commerce,system}.md`, `docs/routes.md`, `docs/final-audit-report.md`.
- **Exclusions:** no new features, no new routes/endpoints/models/tables/columns/enums, no new architecture layers, no new frontend framework, no formatting rewrites, no production access, no commits/pushes unless explicitly requested.

## G. Risks / Guardrails

- **Migrations:** schema is final; NO new migrations. `migrate:fresh` only against local disposable DB.
- **Dead models:** EntityView, Experience, ExperienceProvider, Company — tables absent; must be verified as dead/unused before any documentation claim.
- **Auth:** JWT-based; wrong-auth documentation risk; verify each protected route from middleware + policy source.
- **Payments/webhooks:** Paymob webhook + idempotency (SEC-08) — read-only; no test-account calls.
- **External integrations:** Groq, OpenMeteo, OpenStreetMap, Paymob — audit boundaries via mocks/`--env=testing`, never live calls.
- **API contracts:** frontend excluded by user decision — no contract audit for JS consumers.
- **Rate limiters:** throttle:6,1 etc. — verify from route middleware, don't guess.
- **Test env differences:** tests must run in `phpunit.xml`-configured env; no production data.
- **Concierge + admin analytics/report:** confirm actual scope before documenting (potential dead/partial code).
- **Git rule:** NO commit/push/branch without explicit request.
